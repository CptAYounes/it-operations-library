# Checklists

Checklists in this directory are concise gates for planned work and repeatable verification. The subject guides explain the reasoning behind individual checks.

The boxes are intentionally unchecked so each file can be copied and used for a real piece of work. They do not show repository progress. Mark an item complete only when there is evidence for it; use `N/A` with a reason when a check genuinely does not apply, rather than ticking past an unknown state.

A checklist cannot replace vendor instructions, a change plan or technical judgement. Stop when the starting state, authority or recovery path is unclear rather than checking past an unresolved risk.

Keep the completed copy with the approved change, build or incident record. Useful evidence is concise: timestamp, command or observation, result, exception and owner. Do not paste secrets, full private addressing, recovery keys or unreviewed screenshots into a public copy.
